Haxe in Haxe

The Haxe compiler, ported line by line from OCaml to Haxe and compiled to C by its own backend. Natively it compiles itself faster than the OCaml original, in less memory; here it runs in your browser as WebAssembly.

Playground

The compiler below is the port, built from its own C output with Emscripten. Run type-checks your program and executes it with the port's Eval interpreter (--interp), the same interpreter that runs macros. Compile to HXB emits the compiler's binary module format, the port's first output target. Everything happens locally in a Web Worker; each run starts a fresh compiler instance. The runtime keeps 64-bit pointers, so this is a 64-bit WebAssembly module (memory64): it needs a recent Chrome, Edge or Firefox.

The editor (Monaco) asks the same compiler for completion, hover, signature help and go-to-definition through the JSON-RPC display API that IDEs use, and type-checks as you type. Download

		
One binary for Linux, macOS, Windows and the BSDs, on x86-64 and ARM64, built with Cosmopolitan. It carries the parts of the Haxe standard library it needs, so nothing else has to be installed.

		
haxe-in-haxe.com 17 MB, , commit 


# Linux, macOS, BSD (Windows: rename to .exe)
chmod +x haxe-in-haxe.com
./haxe-in-haxe.com -cp src --main Main --interp                  # run a program
./haxe-in-haxe.com -cp src --main Main --hxb out.zip --no-output # emit HXB
# if your shell can't start it, use: sh ./haxe-in-haxe.com ...

		
Only the x86-64 Linux half has been tested. Code generation for JavaScript, C++, HashLink and the other targets isn't ported: the binary type-checks, runs programs with --interp and writes HXB.

	


	

		
Use hxc

		
The C backend is also a Haxe target for your own programs: the hxc haxelib package. Your Haxe types the program (macros, -lib and IDE support included) and writes HXB; the bundled hxc.com, this port with the backend, reads the archive and writes C; clang, gcc or tcc builds a native binary, or cosmocc a portable one. Threads, sockets, TLS and libuv are supported.


# in a checkout of the repository (needs cosmocc, or NATIVE_CC=clang)
sh hxc/haxelib/build.sh                     # bin/haxelib/hxc.zip
haxelib install bin/haxelib/hxc.zip
haxe -lib hxc -cp src -main Main --custom-target hxc=bin/main
./bin/main

		
HXB is tied to the compiler that writes it, so your Haxe must be the build hxc.com was made from (named in the package's hxc.json). Options (-D hxc.cc, hxc.static, hxc.ssl, hxc.uv, …) are in hxc/haxelib/README.md. The first real program built this way besides the compiler is haxe-formatter, which formatted this project's sources.

	


	

		
Status

		
The goal is a close-to-line-by-line port of the Haxe compiler (haxe/src, pinned upstream commit b10fa6e) that keeps upstream's structure, branch order and data layout. Conformance is strict: for the same invocation, the port must write the same set of HXB modules, each byte-identical to what the OCaml compiler writes.

How it works

		
    
			
  1. Port. Each OCaml module in haxe/src has a Haxe counterpart in src/: records become classes, variants become enums, lists become arrays, with upstream's evaluation order preserved.
    2. 
			
  2. Type itself. The port parses, types and filters its own source, the same pipeline that produces HXB.
    3. 
			
  3. Lower to C. A small backend (hxc/, also Haxe) lowers the typed program to C. Ints and floats are unboxed, generics are erased with boxing at the boundaries, virtual calls go through dispatch tables, and structural field access uses inline caches.
    4. 
			
  4. Runtime. About 8,800 lines of C: a precise generational copying GC with a shadow stack, compact object layouts, real OS threads with stop-the-world collections (green threads under tcc), UTF-16 strings, arrays with unboxed element kinds, exceptions on setjmp, and bindings for sockets, mbedtls and libuv. The standard library is mostly written in Haxe over a few native primitives, including the regular-expression engine.
    5. 
			
  5. Compile the C. tcc compiles the 16 MB file in about a second for development, clang -O2 builds the fastest native binary (gcc -O2 is 4–10% behind), cosmocc the portable one, and Emscripten the WebAssembly on this page.
    6.

Runners

		

			
OCaml reference
The upstream compiler, native OCaml, built from the pinned haxe/ submodule. Every ratio is relative to it.

			
Eval, from source
The reference compiler runs the port's Haxe source with its Eval interpreter: haxe -cp src --run haxe.Main …. Each run first types all 52k lines of the port.

			
Eval, from HXB
The reference loads the port from an Eval HXB archive it wrote once (--hxb-lib haxe-in-haxe.zip --run haxe.Main …) and interprets it, skipping parsing and typing.

			
HashLink JIT, HL/C, JS, JVM, C++
The port compiled by the reference compiler to its existing targets: HashLink bytecode run by hl; HashLink C built with gcc -O2 against a static libhl with a patched allocator; JavaScript on Node; a JAR on the JVM; hxcpp C++ with single-threaded GC marking.

			
hxc: tcc, gcc -O2, cosmocc, wasm
The port compiled by this project's own C backend (hxc/), whose runtime has a precise generational GC. The same C file built with tcc (fast to build), gcc -O2, cosmocc (one portable binary for x86-64 and ARM64; the fat build is measured), and Emscripten: the 64-bit WebAssembly of the playground, built for Node (24, for 64-bit memory) with direct file access instead of the in-memory file system.

		

		
Method

		
Every run is a fresh process compiling one workload with -D disable-parallelism --interp --no-output --hxb out.zip. The table shows the minimum over 3 runs; the Eval runners compiling the port itself ran once, as each run takes about half an hour. CPU is user plus system time of the process and its children: other jobs share this machine, so CPU time, which they disturb less than wall time, is the main measure. It can exceed wall time where a runtime uses several threads (JIT compilation and GC in Node and the JVM). Peak RSS is the largest resident set of the run. Start-up is included: the JVM, Node and Eval pay it on every run. Reproduce with python3 bench/run.py (bench/README.md).
